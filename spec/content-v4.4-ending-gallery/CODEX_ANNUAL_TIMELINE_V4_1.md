# v4.1 연간 진행 정책 — “1년을 건너뛰지 않는다”

## 지금 상태
- 최신 통합 데이터: 핵심 16개 노드 + 확장 65개 사건 + **1~65세 연도별 일상 65개 + 재플레이 범용 후보 12개** + 선택 회수 콜백 26개.
- **집필 데이터는 추가했으나 게임 저장소 엔진에 아직 적용한 것은 아니다.** 코덱스에 마지막 한 번에 넘길 누적 패키지다.
- 0세는 기존 `birth`에서 다룸. 1~65세는 `content/annual_life_events_v4_1.json`으로 채움.
- 같은 나이에 필수 핵심 사건이 있으면 핵심 사건이 우선. 조건 이벤트가 실제로 재생되면 그해의 연도별 일상은 건너뛰어도 됨. **나이를 건너뛰는 것은 금지**.

## 엔진 단일 연간 스케줄러 통합 원칙
1. **주요 노드의 나이로 즉시 점프하지 말 것.** 현재 완료한 나이 `age`, 예정된 핵심 노드 `targetAge`가 다르면 그 사이의 `age+1 ... targetAge-1`을 연간 스케줄러를 통해 진행.
2. 매 해 우선순위: **진행 중 핵심 연속 노드**(같은 해 후속 노드 포함) > `pendingEvents`의 적법한 강제 후속 > 조건/해금 확장 사건 > 해당 해 연간 일상(fallback).
3. 확장 이벤트가 한 해에 존재한다고 해서 그해가 자동 커버된 것으로 간주하면 안 됨. **실제로 UI에 표시되고 방문 기록에 저장된 경우만** 연도 커버를 인정한다. 잠금/조건 미충족/미선택이면 연간 일상 재생.
4. 각 사건을 끝내고 다음 해로 이동하는 시점은 **선택 효과, 연대기, 방문 기록이 하나의 트랜잭션으로 저장된 뒤**. 이벤트 등록만으로 진행 처리 금지. 같은 해 강제 후속은 먼저 완료.
5. 핵심 노드의 `to` 목적지와 엔딩 목적지는 절대 변경하지 말 것. 목적지 나이 > 현재 나이인 경우 **목적지를 `pendingCoreTarget`에 저장**하고 연도별 사건을 소화한 뒤 원래 목적지를 재개. `annual_generic_pool_v4_1.json`은 해당 해의 `category=generic` 일상만 낮은 확률로 교체할 수 있으며 일단 선택된 후보는 회차 시드에 따라 고정할 것. 절대 영구적으로 선행 핵심 노드를 삭제/재배선하지 말 것.
6. 같은 해 여러 핵심 노드(`exam` → `confession` → `confession_afterm` 등) 연결이 있으면 그날 바로 진행. 나이 역행 시 데이터 오류를 출력하고 중지; 종료 상태면 즉시 일상 생성 정지.
7. 특정 나이에 일반 확장 사건을 여러 개 발생시킬지는 기존 안전 제한을 우선. `annual`은 **해당 나이에 풍부한 이야기가 하나도 재생되지 않은 경우에만** 1회 실행. 플레이어가 강제로 일상을 건너뛰는 UI 버튼은 기본 제공하지 말 것.
8. `age`가 단지 현재 장면의 연령을 뜻하고, `currentNode`가 다른 장면의 나이를 가진다면 `currentNode`의 나이를 우선하여 새 게임 초기화(기존 `story.json` 초기 `age=20`, `birth.age=0` 불일치 확인). 단, 이전 저장을 무작정 0세로 리셋하지 말고 migration 규칙/백업 도입.
9. 연간 이벤트 `effects`는 기존 확장 사건의 `{type:"setFlag",value:"..."}`와 동일. `annual_XX_a/b` 플래그는 *선택 완료 후* 부여. 회상 콜백 26개는 해당 플래그가 실제로 존재할 때만 렌더하고 과거의 방문 사건에만 연결. 같은 콜백 중복 표시 금지.
10. 연도별 텍스트에 NPC 초상화를 강제로 연결하지 않는다. 익명 발화/내레이션에 이전 NPC 초상화가 남지 않게 화자 판별 + 종료 시 clear 처리. 기존 56개 이미지는 바이트 변경하지 않음.
11. 신규 연간 이벤트에서는 해당 해의 필수 사건과 모순되는 상황(결혼 확정, 직업 확정, 생존 여부, 미나와 자동 연애 등)을 쓰지 않는다. 피할 수 없는 모순은 조건화하고 주석/감사 보고.
12. 독립적인 속도 옵션을 원하면 시네마틱 연출/애니메이션을 줄이는 것만 허용. 나이 숫자를 건너뛰는 ‘빠른 진행’ 기본값 금지.

## 나이/엔딩 설계 한계
- 고정 스토리 정상 종료 나이: 60, 62, 65세 경로 있음. 기존 조기 엔딩은 해당 나이에 즉시 마침. ‘모든 플레이어가 65세까지 살아야 한다’는 뜻 아님.
- 확장 이벤트에는 65세 이후(최고 69세) 연령 범위가 있으나 기존 핵심 엔딩 구조에서는 보통 도달하지 못함. **66세 이후 임의로 엔딩을 지연하지 말 것.** 후속 장기 루트가 추가되면 66세 이후 일상을 별도로 집필해 확장.

## QA 필수 경로
- 0→12: 1..11세가 모두 표시되어 12세 핵심 등장 (11개 filler 또는 다른 해당 연령 실제 사건); 12세 장면이 두 번 나오지 않음.
- 12→20: 13..19세가 모두 방문되어 20세 시험에 도착. 고백 선택지 포함 최소 네 개 보존.
- 21→29: 22..28세 모두 커버하고 29세 공주 사건 도달.
- 29→41: 30..40세 모두 커버, 41세 감사 사건 도달.
- 47→65: 48..64세 모두 커버하고 65세 조용한 엔딩 도달 (중간 60/62세는 해당 경로의 필수 사건이 아니면 일상 허용).
- 47→60, 47→62: 최종 법정/관리청 등 엔딩 루트까지 매년 방문 기록 연속; `ending`에서 멈춤.
- 조기 엔딩 시 연도 추가 없음. 100개 이상의 시드에서 no skip/duplicate/age regression/soft lock/save-resume를 테스트.
- 연대기 1세당 정확히 1개만 강제하지 말 것: 핵심 연속 노드·추가 사건이 같은 나이에 여러 개 있을 수 있음. 다만 **모든 방문 연령은 1년 간격으로 연속**해야 하고 비어 있는 해가 없어야 함.

## 리그레션 보호
- 기존 코어 16개, 확장 65개, 엔딩 8개, 일러스트 56개 및 이벤트 ID/선택지 ID/분기를 삭제·재설정하지 말 것.
- 본 ZIP은 엔진 자체를 구현했다고 주장하지 않는다. 런타임 적용 시 실제 저장소의 현재 스케줄러를 읽고 차이만 병합해 테스트.
