# 코덱스 적용 지시 — v2.5 본문 문단 공백 및 중복 대사 제거

**목표:** 사진에서 보인 문제를 실제 웹 UI까지 해결. 이 ZIP에는 수정된 JSON과 UI 적용 코드가 함께 있다. `chapters/01_complete.json`의 원문은 **대사/서술 사이에 `\n\n`(빈 줄 하나)**를 저장한다.

## 필수 구현
1. 기존 콘텐츠의 `story.json`, `chapters/01_complete.json`, `endings.json`, `ending_cinematics.json`, `characters.json`을 현재 프로젝트 데이터 구조에 맞게 통합한다. 기존 사용자 저장/엔딩 갤러리를 삭제하지 않는다.
2. `node.body`는 `\r\n`을 `\n`으로 통일하고 **빈 줄(`\n\n`) 기준으로 분리하여 `<p class="story-paragraph">`**로 렌더링한다. **각 `<p>` 사이 `margin-block: 0 1.15em`**을 적용하고 line-height 1.75로 한다. 대사→대사, 대사→서술, 서술→대사 모두 빈 공간이 보여야 한다. **`white-space: pre-line`만 적용하는 것은 불충분**하다.
3. 본문에 이미 있는 큰따옴표 대사를 `presentation.nodes[id].dialogues`/`dialogues`/`lines`/`speakerCards` 등에서 **두 번째로 출력하지 않는다**. 기존 데이터/저장 불러오기에도 중복이 없어야 한다. 별도 대사 UI를 무조건 추가하는 코드를 제거하거나 `body`에 대사가 있으면 숨긴다.
4. `outcome.narrative`도 같은 문단 렌더러로 선택 직후 **한 번만** 출력한다. 기존 선택 로직·효과·엔딩은 유지한다.
5. React 사용 시 `web/StoryParagraphs.tsx` 예시를 참조하고, 다른 프레임워크면 동등한 구현으로 옮긴다. 본문을 `innerHTML`로 삽입하지 말 것(XSS 방지).
6. UI의 현재 스토리는 본문만, 과거 기록은 짧은 요약만 표시한다. `선택지 보기`는 기존대로 유지해도 좋다.

## 검수 조건
- 모바일에서 각 서술과 대사 사이에 **실제로 빈 줄에 해당하는 시각적 간격**이 있다.
- 연속된 두 대사 사이에도 동일한 간격이 있다.
- 본문 하단에 동일한 발화가 이름표 카드로 반복되지 않는다.
- 새 게임과 기존 저장 불러오기 모두 동일하다.
- 7개 엔딩 및 조기 엔딩이 여전히 연결된다.
