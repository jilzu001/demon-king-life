# v2.9 코덱스 통합 적용 지시서 — 새 엔진 단일화 + 직접 집필 사건/조건부 사건/회차 해금

## 작업 목표 및 순서
1. `CODEX_REMOVE_ORIGINAL_V2_8.md`를 적용해 원작 플레이 런타임·UI·진입 경로를 **완전히 제거**한다. 원작 자료는 개발 참고용으로만 남기고 사용자 저장 데이터는 지우지 않는다. 설정에 **타이틀로 돌아가기**를 추가하고 현재 회차를 먼저 안전하게 저장한다.
2. 현재 v2.7 콘텐츠(16개 장면, 8개 엔딩), 고백 선택지, 모바일 문단 빈줄, 한 줄 연대기, 엔딩 도감을 **유지**한다. 이미 프로젝트에 있는 동일 버전 파일은 불필요하게 덮어쓰지 않는다.
3. 다음 세 층을 **새 엔진의 기존 이벤트 선택기에 통합**한다. 별도의 원작 엔진이나 플레이 모드를 만들지 않는다.
   - `core`: 직접 집필한 고정 주요 사건. 출생/미나 시험/국가 지정/예산/재판 등 인과적 줄기.
   - `conditional`: 조건에 따라 본문·대사·선택지가 달라지는 직접 집필 사건. 미나 관계, 왕실 신뢰, 돈, 범죄 기록, 생존 여부, 나이, 이전 선택 등을 사용.
   - `unlock`: 엔딩 후 회차 횟수·엔딩 종류에 따라 다음 회차에서만 등장 가능한 새로운 인물/사건/엔딩. 해금은 **추가**일 뿐 기존 필수 스토리를 빼앗지 않는다.
4. 이 ZIP의 `content/events_v2_9.json`은 **새 엔진 확장 포맷의 실제 시범 콘텐츠**이다. 코덱스는 기존 장면 JSON 스키마와 별도 레지스트리로 안전하게 병합하고, 아래 명세대로 실제 실행 코드를 작성한다. 예시 사건만 추가하고 '수백 개 콘텐츠 구현 완료'라 주장하지 않는다.

## 상태/데이터
- 새 회차 상태(run): `age`, `player`, `npcs`, `flags`, `visitedEventIds`, `pendingEvents`, `history`, `currentNode`, `endingId` 등. 기존 필드명과 호환 계층을 사용. `flags`는 문자열 배열로 직렬화.
- 영구 메타 상태(meta): `schemaVersion`, `completedRuns`, `unlockedEventIds`, `unlockedCharacterIds`, `endingGallery`, `seenEventIds`. **새 회차 시작 때 초기화 금지**.
- 기존 도감 및 저장 포맷을 검토하여 마이그레이션. 기존 저장에서 `completedRuns`가 없지만 도감에 엔딩이 있다면 무조건 0회차로 되돌리지 말고 도감과 저장 이력에 근거해 안전하게 산출. 모호하면 원본 보존 및 보수적 해금.
- 중복 실행 방지: 사건 `oncePerRun`, 영구 최초 1회 `onceEver`, 조건 충족 때마다 가능 `repeatable`(기본 false). 사건 완료 시 선택 결과/연대기를 원자적으로 저장.
- 이전 회차의 인물 관계 수치를 다음 회차에 그대로 가져오지 않는다. 영구 메타는 해금만 결정.

## 사건 선택 알고리즘
1. 진행 중인 고정 핵심 노드/강제 후속 사건이 있으면 그것을 우선 실행한다. 기존 `choices[].outcomes[].to` 연결을 임의로 끊지 않는다.
2. 핵심 사건 사이 **안전한 간격**에서만 `conditional`/`unlock` 후보를 평가한다. 나이/상태/해금/이미 방문/선행 사건/충돌 그룹 확인.
3. 후보가 여럿이면 `priority` 우선, 동일 우선순위에서 시드 기반 가중 선택. RNG 시드는 회차 저장에 포함해 새로고침해도 결과가 바뀌지 않게 한다.
4. 선택은 대체로 찬성/반대 + 맥락에 맞는 황당한 선택(최대 3개). 황당 선택도 현실적인 후폭풍과 인과를 작성. 조기 사망/처형/파산 엔딩은 예고 가능한 위험 신호를 포함.
5. 후보가 없어도 핵심 스토리는 막힘 없이 계속된다. 연령 역행, 사망 NPC의 재등장, 불가능한 중복 사건 방지. 엔딩 확정 후에는 어떤 사건도 실행하지 않는다.
6. `body`는 문단 사이 `\n\n`으로 저장, 렌더링 시 `<p>`로 나눠 여백 적용. 본문에 있는 대사 카드 중복 출력 금지. 연대기는 `chronicleSummary` **한 문장만**.

## 조건식 DSL (eval 절대 금지)
- `all`, `any`, `not`, `gte`, `lte`, `eq`, `hasFlag`, `metaCompletedRunsGte`, `metaHasEnding`, `metaUnlocked`만 허용하는 선언형 조건 평가기를 만든다. 임의 JS 코드 실행 금지.
- 조건 없는 사건은 `conditions: {"all":[]}`. 경로는 미리 허용된 상태 키만 접근. 조건을 만족하지 않는 선택지는 숨기거나 비활성화하되 사용자에게 이유를 설명한다.
- 효과도 allowlist: `setFlag`, `addStat`, `setRelationship`, `unlockEvent`, `unlockCharacter`, `queueEvent`, `endRun`. 효과 처리 후 검증, 원자 저장. 모든 엔딩은 기존 엔딩 시퀀스로 연결.

## 콘텐츠 확장/작업 보호
- `content/events_v2_9.json`의 샘플을 실제 게임에 연결하고, 작성자에게 JSON 파일만으로 인물/대사/조건/선택/해금/엔딩을 추가할 수 있게 한다.
- 새로운 인물은 첫 회차 엔딩 뒤 **다음 회차부터** 출현. 미나/에리시아/왕과의 관계는 조건부 사건으로 재활용 가능.
- 현재 v2.7 스토리 JSON, 엔딩 JSON, 엔딩 연출, UI 기능을 임의 삭제하지 않는다. 테스트용 임시 해금/디버그 버튼은 운영 UI에 남기지 않는다.
- 개발자 문서에 데이터 형식/조건/우선순위/상태 저장/작업 보호 규칙을 명시한다.

## 필수 자동 테스트
- 모든 사건 ID 유일, 선택 ID 유일, 참조 대상 존재, 조건/효과 DSL 유효.
- 1회차에 `unlock` 사건이 노출되지 않음. 엔딩 후 2회차에 등장 가능. 새 회차 이후 도감 보존.
- 관계 조건이 반대인 사건은 동시에 실행되지 않음. 죽은 인물 등장 불가.
- 100개 이상의 서로 다른 시드로 자동 플레이, 모든 도달 가능한 엔딩 확인, 막힌 경로·무한 반복·나이 역행 탐지.
- 타이틀 이동/이어하기, 새 회차/해금, JSON 백업 복원, 기존 저장 마이그레이션, 모바일 가독성 확인.
- UI에서 원작 플레이/원작 복원/구형 엔진 버튼 및 실행 경로 0개 확인.
- 실제 변경 파일·테스트 결과·미완성 항목을 보고. 구현 못한 부분은 구현했다고 쓰지 말 것.
