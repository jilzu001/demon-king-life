# 코덱스 적용: 본문 한 번만 출력 / 웹소설 문단 간격

이 ZIP은 v2.3의 분기, 엔딩, 상태 효과를 유지하고 `chapters/01_complete.json`의 `body` 및 선택 결과 `narrative`를 웹소설식으로 정돈한 v2.4 콘텐츠입니다.

## 필수 UI 변경
1. `node.body`를 **하나의 본문**으로 출력한다. 원문 `\n\n`을 빈 문단 간격으로 보존한다. `white-space: pre-line` 또는 문단별 `<p>` 렌더링 권장. 단순 공백 병합이나 `textContent` 처리 과정에서 줄바꿈을 제거하지 않는다.
2. 본문에 큰따옴표 대사가 이미 있으므로 `presentation.nodes[id].dialogues`, `dialogues`, `lines`, `speakerCards` 등 **같은 사건의 별도 인물 대사 카드는 렌더링하지 않는다**. 본문 아래에 다시 나오는 대사 중복을 반드시 없앤다. 구형 저장 데이터에서도 동일하게 적용한다.
3. 대사는 본문 내 독립 문단, 서술은 사이사이 독립 문단. 각 문단 간 0.85~1.15em 여백, 줄간격 1.65~1.85, 모바일 본문 폰트 16~18px 권장.
4. 선택 결과 `outcome.narrative`는 선택 직후 1회만 표시한다. 이미 이력을 통해 표시한 결과를 현재 장면에 다시 붙이지 않는다.
5. 인생 기록은 방문한 사건의 `chronicleSummary`나 제목으로 짧게 유지하며, 본문이나 대사 전문을 중복 표시하지 않는다.
6. 선택지는 본문 끝에만 2~3개 표시한다. 기존 엔딩/선택 로직은 변경하지 않는다.

## 회귀 테스트
- `exam` 장면에서 본문 대사 뒤에 별도 대사 카드가 추가로 나타나지 않아야 한다.
- “시험장은 조용해졌다.” 같은 서술 다음에 빈 줄, 큰따옴표 대사 다음에 빈 줄이 보이는지 모바일에서 확인한다.
- 페이지를 새로고침하고 기존 저장을 불러와도 중복 대사 카드가 나오지 않아야 한다.
- 기존 엔딩 7개와 조기 엔딩 진입 동작이 유지되어야 한다.
