## 0. 가장 중요한 원칙

사용자는 이전 20개 엔딩과 이전 스토리 구조를 보존 대상으로 **지정하지 않았다**. 이제 작가가 작성한 새 판의 **8개 독립 인생 경로와 새 엔딩 32개**를 기준으로 게임 콘텐츠를 개편한다. 기존 루트를 끼워 넣거나 이전 엔딩 제목만 재사용해 숫자를 맞추지 말 것.

**하지만 엔진/저장 데이터의 물리적 보존은 별개의 안전 문제다.** 작업 전에 저장소/기존 공개 빌드와 이용자 세이브를 안전하게 백업한다. 현재 다른 Codex 작업에서 개선 중인 **실제로 방문한 분기의 색상 구별 기능도 절대 덮어쓰지 않는다.**

새로운 원고를 **코덱스에서 재집필하지 말 것**. ZIP의 실제 텍스트·선택·후속 조건·결말을 구현한다. 오류나 논리 모순이 확인되면 범위를 좁혀 수정하고 근거를 보고한다.

**코덱스에서는 신규 AI 일러스트를 생성하지 말 것.** 동봉된 승인 후보 WebP 4개와 이미 보유한 자산을 먼저 비교하여 재사용하며, 새 이미지가 필요한 장면은 제작 대기로 보고한다. `ILLUSTRATION_BRIEFS.json`에 준비된 상세 프롬프트는 ChatGPT에서 순서대로 제작할 용도다. 아직 없는 이미지를 있다고 보고하거나 접합/합성/임시 이미지로 대체하지 말 것.

## 1. 사전 점검 및 보호

- `git status --short`, `git branch --show-current`, `git log -1`, `AGENTS.md`, `CONTENT_CANON.md`, `DEV_PROGRESS.md`, `CHANGELOG.md`를 확인한다.
- 미커밋·미푸시 변경사항을 임의로 초기화하지 않는다. 다른 Codex 세션이 동일 파일을 편집 중이라면 작업을 분리하고 충돌 해결 전에는 덮어쓰지 않는다.
- 원본 2.x 콘텐츠와 저장 구조를 되돌릴 수 있도록 안전한 백업/별도 커밋을 만든다. `git reset --hard`, 무조건 덮어쓰기, 기존 저장소 삭제 금지.
- 사용자의 최신 자유 개편 지시를 최우선으로 하되, **본문 메인 UI 전체 리디자인은 요청하지 않았음**. 이미 승인된 트리/도감 개선을 제외한 본문 UI는 유지한다.

## 2. 적용할 신규 콘텐츠

ZIP의 `content/`는 새 스토리 버전 5.0.0에 맞춘 엔진 스키마 형식이다.

- `story.json`: manifest, `id=demon-king`, `version=5.0.0`, 엔트리 `birth`.
- `chapters/01_common.json`: 0세 출생 → 12세 미나 → 20세 용사 시험 → 네 가지 진입 관문.
- `chapters/02_fugitive.json`: 추방자의 길 / 비폭력 저항의 길.
- `chapters/03_reform.json`: 증거를 지키는 길 / 피해자 집단 소송의 길.
- `chapters/04_money.json`: 안전한 유료 토벌 사업 / 회계 투명성과 왕국 정치의 길.
- `chapters/05_mina.json`: 구호와 구조대의 길 / 고백·자유로운 관계의 길.
- `endings.json`: 기존 20개와 무관하게 새로 집필한 **32개 독립 엔딩**.
- `characters.json`: 이전의 핵심 인물 인격을 존중하되 필요에 따라 갱신.
- `docs/ROUTE_MATRIX.json`, `ENDING_CATALOG.json`, `EXAMPLE_ROUTES.json`: 재구성된 연결·엔딩 집합·경로 근거.

총계: **47 scene / 106 choice / 106 outcome / 32 ending**. 정적 전체 선택 경로 **864개**가 검증되었다. 정적 검사는 실제 엔진 시뮬레이션을 대신할 수 없다.

이전 20개 엔딩이 남아 있지 않아도 **요구사항 위반이 아니다**. 단 기존 버전 저장과 공개된 이전 콘텐츠는 백업하고 복구 가능해야 한다.

## 3. 실제 저장소에 붙이는 방법

1. ZIP은 프로젝트 밖 임시 폴더에 압축해제한다. 작업할 브랜치 및 현재 공개판의 파일 구조를 먼저 확인한다.
2. `content/`의 파일들을 신규 버전 콘텐츠로 도입한다. 이 프로젝트는 `public/stories/demon-king-compact/story.json`을 기본으로 읽는다. 사용자 동의 없는 무차별 오버라이트 대신 기존 공개 콘텐츠를 백업하고 **새 버전 파일 전부가 설치된 뒤** manifest를 마지막에 전환한다.
3. 게임 엔진 `src/engine/transition.ts`의 **조건/이동/결말 데이터 계약**으로 새 콘텐츠를 실행한다. 이번 변경을 이유로 확률 엔진이나 선택 시스템 자체를 재개발하지 않는다.
4. 현행 `src/content/compact-contract.ts`의 `isCompact()`는 2.2/2.3 버전만 인식하므로, 5.0의 컨텐츠 분류·렌더링 분기·save-key 처리 영향부터 평가한다. 5.0에 필요 없는 구버전 어댑터(legacy `bad`/`good` 변환)를 무턱대고 적용하지 않는다. 신규 `endings.json`은 이미 스키마의 `happy|normal|bad|bittersweet|hidden|absurd` 범위로 작성됨.
5. 이전 버전과 달리 새 콘텐츠엔 임의의 이전 엔딩 ID를 재사용하지 않는다. 버전별 저장 키/엔딩 수집 키를 분리하고, 기존 저장/회차 기록의 자동 변경·리셋·허위 마이그레이션을 금지한다. 예전 저장을 새 스토리로 억지 복원하지 말고 버전 안내/백업을 제공한다.
6. 현재 `src/content/ending-gallery.ts`는 **기존 20개 엔딩에 대한 하드코딩 검사**가 있으며 32개를 그대로 수용하지 못한다. **새 JSON 엔딩 목록에서 도감 항목을 동적으로 구성**하도록 조정한다. UI는 기존 외형을 최대한 유지하고, 새 엔딩 중 이미지가 아직 없는 것은 잠금·일러스트 미제작을 정직하게 표시한다. 레거시 20개 카탈로그 검사를 단순히 삭제하는 게 아니라 신규 판/구판에 따라 분리한다.
7. 엔딩 트리는 이전 `ending-tree.json`의 대표 엔딩 경로 하나씩을 합치는 방식이 아니라 새 `Story.nodes`와 `choices[].outcomes[].to`에서 **전체 47개 사건·106개 선택·32개 엔딩 및 정확한 합류 구조(DAG)**를 생성한다. 노드는 한 개 ID로 관리, 다중 부모 연결을 표현할 것. 모드 전환 없이 전체 그래프 기본 표시. 기존 **방문 경로 색상 강조** 유지. 미방문 노드의 결말 본문 및 그림은 잠금 상태 유지.
8. `src/ui/ending-tree-layout.ts`의 `parentId` 기반 1부모 트리 레이아웃은 DAG에서 한계를 가지므로, 트리 전용 레이아웃을 분기·합류 대응 알고리즘으로 바꾸되 스토리 엔진의 노드 계약은 변경하지 않는다. PC 휠/드래그·모바일 핀치·미니맵·재선택 방지/확인 유지.
9. `src/ui/illustrations.ts`의 `renderStoryArtwork` 경로 정규식에는 `event_cg_v50` 새 디렉터리가 없다. **필요한 신규 카테고리만 허용하고** `illustrations/asset_mapping.json`의 nodeId·age·image size 및 실제 WebP 존재 여부를 검사하며 매핑한다. 이미지가 없으면 UI가 정상 작동해야 한다.
10. 0세, 12세, 20세 등 기존 동일 사건 ID의 이미지가 현재 GitHub에서 정확한 장면이면 재사용한다. ZIP 4개는 이전 대화의 별도 장면 그림 재압축본이므로 원본과 맞는지 먼저 시각 대조한다. 특히 출생 장면에 성인 주인공·미나를 부모로 끼워넣는 오류 금지.
11. 기존 일상 한 문장/주마등/엔딩 연출/캐릭터 초상화가 **존재하지 않는 옛 사건/옛 엔딩을 노출하지 않도록** 새 콘텐츠 기준으로 정확히 업데이트한다. 플레이하지 않은 다른 루트의 사건을 본 것처럼 말하지 않는다.
12. 노후화한 엔딩 갤러리, route-years/연대기, 도감 테스트에서 기존 20개의 수를 기대하는 하드코딩은 **v5 기준으로 맞추되, 이전 버전 회귀 검사 파일은 보존 또는 분리**한다.

## 4. 일러스트 처리 (정확한 상태 필수)

- ZIP `illustrations`에는 이전 대화에서 제작한 단독 장면 WebP **4개**를 저용량으로 재인코딩해 동봉했다. **이번 작업에서 신규 그림 생성 0개**다. 이것을 '새 삽화 전부 제작 완료'로 보고하지 않는다.
- `illustrations/asset_mapping.json`의 `originalSource` 및 `nodeId`, `age`를 검토한다. 실제 장면과 불일치하는 경우 매핑을 보류하고 기존 GitHub 그림을 우선 재사용한다.
- `docs/ILLUSTRATION_BRIEFS.json`에 신규 CG용 12개 및 결말 32개 **상세 장면별 생성 프롬프트**가 있다. 향후 ChatGPT에서 한 장씩 제작할 작업 큐다. 코덱스에서 자동 이미지 생성 금지.
- 현재 GitHub의 `event_cg_v4_5`, `event_cg_v4_6`, `characters` 등 공개 이미지와 사용자 로컬의 `.codex/generated_images`를 먼저 조사해 적합한 기존 그림은 중복 제작하지 않는다.
- 새 파일은 WebP 960px 가로, 목표 약 40~120KB. 모바일 320/390/430px에서 배경/얼굴/구도 검수. 이 파일이 실제 없는 경우 텍스트로 계속 진행할 수 있게 한다.
- 이전처럼 캐릭터 시트의 얼굴을 잘라 사건 CG처럼 붙이거나 일러스트 모음집에서 패널을 오려 쓰지 않는다.

## 5. 필수 테스트 / 완료 기준

- `npm run typecheck`, `npm test`, `npm run validate:content`, `npm run simulate:all`, `npm run check`; 관련 Playwright 모바일/PC 테스트.
- 스토리의 47개 사건, 106개 선택과 결과, 32개 엔딩의 ID·연결·실행 조건을 대조. 정적 검사 결과는 `docs/STRUCTURAL_CHECK.json`에 있음.
- 새 엔딩 각각 실제 엔진 `createRun/choose`를 통해 도달 가능한지 확인. ZIP `EXAMPLE_ROUTES.json` 32개 예시를 사용해 검증, 엔딩 번호/내용 일치 여부 검사.
- 8개 하위 삶의 **실제 중반/후반 사건과 결말이 서로 다른지** 검증. 외형만 다르고 같은 공통 사건으로 돌아가는 루트가 없는지 확인.
- 이전 대화/입법/회계/미나 서사의 논리 규칙 보호: 12세 첫 만남, 전투력 2 vs 8402, 동의 없는 혼인 금지, 특별계정 이체=횡령 확정 아님. 조건 충족 이전에 120,000 금화 허위납품 확정 사실을 폭로하지 않음.
- 실제 선택한 경로는 기존 색상 강조. 플레이하지 않은 경로에 방문 상태를 부여하지 않음.
- 노드 클릭/드래그만으로 엔딩 획득, 저장 수정, 미방문 노드로 점프 불가.
- 구버전 세이브와 도감 원장을 손실 없이 복원할 수 있고, 새 판과 데이터가 혼합되지 않음.
- 음향/BGM 추가 금지, 본문 UI 전면 리디자인 금지.
- **새 이미지 미제작 44개는 개별 제작 대기로 표시**: 신규 CG 12, 결말 32. 텍스트/분기 적용이 완료돼도 미제작 일러스트를 완료로 보고하지 않음.
