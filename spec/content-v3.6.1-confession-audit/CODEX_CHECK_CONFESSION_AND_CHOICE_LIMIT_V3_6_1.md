# CODEX 긴급 점검: 20세 미나 고백 선택지 누락 (v3.6.1)

## 목표
실제 실행 화면의 20세 「용사 시험의 실기 과목」에서 반드시 `미나에게 사랑한다고 고백한다.` 선택지를 표시하고, 선택 시 고백 결과와 후속 관계 분기가 정상 동작하도록 수정한다.

## 확인된 근거
- 패키지 `chapters/01_complete.json`의 `exam` 노드에는 `confess` 선택지가 **이미 존재**한다. 다만 문구는 `미나에게 오래전부터 좋아했다고 고백한다.`이고 선택지는 총 3개다.
- 사용자가 보내준 실제 실행 화면에는 다른 세 선택지(공격/항의/출연료)가 나타난다. 따라서 패키지에 고백 데이터가 있다는 사실만으로 실게임에 적용됐다고 판단하지 않는다.
- 현재 제공된 ZIP은 실제 GitHub 프로젝트의 엔진 소스 전체를 포함하지 않는다. **실제 원인은 코덱스가 프로젝트를 열어 조사해야 한다.**

## 필수 점검 A — 데이터 출처 및 분기
1. 실행 화면에서 20세 시험 장면이 렌더링될 때 참조하는 이벤트 ID, 파일 경로, 로더 함수, 최종 choices 배열을 추적한다.
2. 코어 `chapters/01_complete.json`의 `exam`, 확장 `content/events_v2_9.json`, 게임 저장 데이터, 변환/빌드 산출물, 하드코딩 이벤트의 중복 및 우선순위를 조사한다.
3. 데이터가 구버전이거나 선택지가 변환 중 사라졌다면 원본을 한 곳에서 수정하고, 중복된 데이터 소스가 다시 덮어쓰지 않게 한다.
4. `미나에게 사랑한다고 고백한다.` 선택지는 **실제로 실행되는** 시험 이벤트에 반드시 포함한다. 기존 공격·항의·출연료 선택지를 임의 삭제하지 않는다. 필요한 경우 총 4개 이상 선택지로 구성한다.
5. 고백 결과는 미나의 반응, 관계 상태, 이후 회상/주마등과 연결한다. 기존 `confess` 후속 노드가 유효하면 재사용하되 노드·선택지 ID 및 저장 호환성 보호. 기존 이벤트 스키마에 맞는 결과와 effect를 작성한다. 실제 이벤트 ID를 추측해서 임의 생성하지 않는다.

## 필수 점검 B — 엔진의 3개 제한 및 표시
1. UI `slice(0,3)`, `take(3)`, CSS 고정 높이·overflow hidden, 배열 길이 검사, 선택지 인덱스 0~2 하드코딩, 데이터 검증 스키마 maxItems=3, 랜덤 3개 추출 등을 검색한다.
2. 최종 데이터 배열에 4개가 있는데 3개만 보이는지, 애초 데이터가 3개인지 런타임 로그로 구분한다.
3. 4개 이상일 때 PC/모바일에서 전부 보이고 클릭 가능한지, 스크롤과 모달 크기, 화면 가림 및 키보드 포커스를 확인한다.
4. 선택지 개수는 이벤트 데이터가 결정한다. 일반 사건마다 반드시 4개를 만들 필요는 없다.

## 검증 기준 (실제 테스트 필수)
- 20세 미나 시험에 공격·항의·출연료·`미나에게 사랑한다고 고백한다.`가 모두 표시된다.
- 고백 클릭 시 올바른 결과 및 미나 관계 플래그/후속 분기가 작동한다.
- 2·3·4·5개 선택지 테스트에서 모든 선택지를 선택할 수 있다.
- 저장/불러오기, 이전 사건, 기존 엔딩, 주마등 회상에 회귀 오류가 없다.
- 데스크톱/모바일 뷰포트에서 마지막 선택지가 가려지지 않는다.
- 실제 테스트하지 못한 항목은 미검증으로 표시한다.

## 보호 및 기록
- 기존 정상 선택지, 이벤트/선택지 ID, 저장 데이터, 사건 조건, 엔딩을 임의 삭제·초기화하지 않는다.
- 기존 `AGENTS.md`, `DEV_PROGRESS.md`, `WRITING_PROGRESS.md`, `CHANGELOG.md`가 있다면 읽고 중복 생성하지 않는다.
- 수정한 파일, 실제 원인(데이터 vs 엔진 vs 둘 다), 테스트 명령 및 결과를 개발 기록에 남긴다.
- 본 ZIP의 콘텐츠를 무조건 프로젝트에 덮어쓰지 않는다. 최신 프로젝트 코드와 비교 후 필요한 변경만 적용한다.
