## 1. 여기서 집필된 콘텐츠를 실제 적용

- ZIP `04_v48_independent_life_routes.json`은 **새 문안 완성 데이터**이며 브레인스토밍 아이디어가 아니다. 기존 프로젝트의 chapter 관례 및 schema에 맞춰 `public/stories/demon-king-compact/chapters/04_v48_independent_life_routes.json`로 넣는다. 데이터 키 필드가 최신 버전에서 달라졌다면 최소 변환하고 원본 본문을 보호한다.
- `routing_patch.json`에 따라 기존 `exam`의 `attack`, `refuse`, `invoice`, `confess` **각각 첫 outcome의 목적지**만 신규 `v48_*_gate`로 변경한다. **선택 텍스트/choice ID/outcome ID/effects를 삭제하거나 재생성하지 않는다.** 최신 로컬 파일이 이와 달라졌으면 패치를 멈추고 충돌을 보고한다.
- manifest의 `chapters` 마지막에 `chapters/04_v48_independent_life_routes.json` 추가. 기존 chapter 삭제 금지. 중복 등록 금지.
- 각 신규 `v48_*_gate`의 첫 선택으로 옛 `prison`, `petition`, `invoice`, `confession` 경로로 복귀할 수 있다. 기존 20개 엔딩 전체는 구형 루트를 통해 계속 도달해야 한다.
- 나머지 2개 선택은 독립 루트로 진입한다. 총 8개 하위 루트에서 **21세 / 중년 / 노년 결단**의 서사가 자체적으로 진행된다. 기존 고유 스토리 텍스트를 불필요하게 재작성하지 않는다.
- 신규 사건은 `age`의 시간 진행 및 chronicle의 연도 기록과 충돌하지 않도록 엔진의 실제 age 동작 확인. `flags` 추가 동작/효과 조건을 검사한다.
- 각 8개 하위 루트의 중년 선택에서 `protect`만 고르면 첫 엔딩, `delegate`만 고르면 둘째 엔딩, `record`를 고르면 양쪽 엔딩이 가능하다. `enabledWhen` 조건이 실제로 평가되는지 테스트. 중년 선택의 내용이 곧바로 결말 선택 범위를 바꾼다는 사실을 보존할 것.
- 중요한 기존 선택과 분기 일부가 집필과 다르게 변형되었다면 무리한 자동 수정 대신 충돌 지점을 보고한다.
- **엔딩 본문과 루트 결말 사이의 필연적 인과·동의·사건 이력 감사**가 매우 중요하다. 신규 직접 엔딩 도달은 필수 장면, 플래그, 인물 동의 등을 충족해야 한다. 예컨대 `ending_mina_wedding`은 미나의 실제 동의 없는 결혼이 돼선 안 되므로 결말 전 분기를 증강하거나 잘못 연결된 선택은 닫고 재검토한다. `ending_fire`는 서류 방화의 실제 선택 결과이며 미화하지 않는다. `ending_ledger`는 실제 증거 절도 후에만 연결된다.

## 2. 전체 분기 트리 개선

기존 `src/ui/ending-tree.ts`, `ending-tree-layout.ts`, `tree-camera.ts`와 현재 구현 중인 방문 분기 색상 로직을 보존하며 통합한다.

- 하나의 전체 분기 그래프가 기본 화면이며 모드 전환 없음. **새 28개 사건 / 76개 선택 / 76개 결과를 포함한 실제 스토리 전체**를 원본 JSON 및 엔진 연결 규칙에서 생성. 20개 엔딩 대표 경로 합성으로 대체하지 말 것.
- 미방문 분기 구조 전부 표시. 이미 진행한 사건·실제 선택한 연결선은 **현재 색상 시스템**으로 강조. 과거에 선택하지 않은 분기를 방문 처리하지 않음.
- 실제 합류는 하나의 사건 노드로 표현. 조건부 여부, 엔딩 잠금(결말 텍스트/CG), 노드 검색, 경로 탐색, 접기/펼치기, PC 드래그/휠, 모바일 터치/핀치, 미니맵 유지.
- 노드 클릭/드래그는 세이브/진행 상태 변경 금지. 실제 방문한 사건에서만 기존 재선택 API 호출.
- 정적 간선과 상태상 진짜 도달 가능성을 구분. 불확실하면 미검증으로 표기.

## 3. 저용량 일러스트: 작업 지시만 ZIP에 포함되어 있음

- `illustration_prompts.json`의 20개 장면 제작 지시를 따른다. **각 파일은 실제 그림 파일로 생성해야 완료**이다. 이미지 생성 도구가 없다면 `이미지 제작 대기`로 정확히 표시, 기존 콜라주/사람 얼굴 크롭/단색 플레이스홀더를 완성으로 간주하지 말 것.
- 프로젝트에서 사용자가 승인한 0세 출생신고 그림을 시각적으로 먼저 참고: **갈색 머리 평범한 아버지 + 갈색 머리 어머니가 검은 머리 신생아 안음 + 안경 쓴 파란 관복 서기관**. 주인공=검은 머리 청년, 미나=긴 은백색 머리/푸른 눈/남색·은색 갑옷, 레온과 혼동 금지. 출생의 부모를 성인 주인공/미나로 바꾸지 말 것.
- 기존의 채택된 따뜻하고 부드러운 판타지 웹소설 삽화 스타일을 동일하게 유지. 완전한 장면 CG, 배경·인물 위치 자연스럽게 통합, 모바일 안전 여백. 승인 기준 없으면 시안 검수 요청.
- 저용량 WebP, 일반 40~120KB 목표, 중요한 CG 150KB 이하 권장(화질 우선), 실제 크기와 파일 존재 확인. 기존 자산 매니페스트·지연 로드·연결 규칙 사용, 조건을 방문하지 않았으면 해당 그림 표시하지 않음.
- 외부 이미지 생성 서비스 사용이 현재 Codex 환경에서 불가능하면 실제 제작 불가를 사용자에게 알리고 프롬프트/연결 TODO만 남길 것.
