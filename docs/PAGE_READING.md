# 페이지 방식과 기존 스크롤 방식

하단 읽기 상태 문구 오른쪽에 **페이지 방식** 버튼을 추가했다. 기본은 기존 스크롤 방식이다. 페이지 방식으로 바꾸면 버튼은 **스크롤 방식**으로 표시하며 언제든 되돌릴 수 있다.

페이지 방식은 사용자 추가 지시대로 **한 페이지 분량을 즉시 표시**한다. 자동 줄 표시/자동 넘김/자동 스크롤을 실행하지 않는다. 본문을 누르거나 **다음 페이지** 버튼으로 넘기고 **이전 페이지**로 돌아갈 수 있다. 마지막 페이지를 읽고 **선택지**를 누르면 선택 팝업을 연다. 선택 후 서술도 같은 방식으로 표시하고 **이어서**로 다음 사건을 연다. **스킵**은 기존처럼 읽기를 완료하고 선택/다음 사건으로 진행한다. 결말 회상도 페이지 방식을 선택한 경우 자동 넘김을 끈다.

CSS의 다단 조판으로 실제 창 크기와 글자 크기에 맞춰 페이지를 나눈다. 문단이 한 페이지보다 길면 문단 안의 줄에서도 분할하므로 긴 문단/대사가 잘리지 않는다. 원문을 HTML로 파싱하거나 재작성하지 않고 기존 문단 DOM을 유지한다. 페이지 전환은 콘텐츠의 수평 위치를 한 페이지 단위로 바꾸며 세로 스크롤을 움직이지 않는다. ResizeObserver와 전체 글자 크기 변경 감시로 가로/세로 회전·창 크기·100~150% 글자를 반영한다.

설정은 세이브와 별도 `demon-king:ui:reading-mode` 키에 저장한다. 새로고침 뒤 선택한 방식은 유지하지만 현재 장면의 페이지는 첫 페이지부터 다시 읽는다. 장면 안에서 메뉴를 열고 닫으면 같은 페이지를 유지한다. 방식 전환으로 엔진/seed/선택 결과/재산/관계/전과/도감을 변경하지 않는다. 기존 스크롤 방식의 천천히 자동 표시·클릭당 다음 한 줄·빠르게·일시정지는 유지한다. 지난 사건 재선택도 유지하며 다시 선택할 때는 기존대로 선택 팝업을 바로 연다.

## 검증

- 전체 검사: 단위/통합108개와 브라우저92개, 총200개. 타입·JSON·원작/축소판 전수 분기·빌드 검사도 실행한다.
- 새 PC/모바일8개 검사는 즉시 전체 페이지 표시, 자동 넘김/스크롤 없음, 이전/다음/마지막 페이지 선택 게이트, 선택 후 서술, 새로고침, 모드 전환/회차 보호, 가로 화면/글자 변경을 검사한다.
- 긴 문단과 150% 글자로 작은 화면에서 모든 글자의 DOM Range 좌표를 페이지마다 비교하여 모든 글자가 정확히 한 페이지에 나타나는지 검사한다. 단순히 원문 문자열만 남아 있는지를 검사하는 방식이 아니다.
- 실제 빌드: `npx tsx scripts/verify-pages-ui.ts http://127.0.0.1:4175/ --screenshots`. PC1280×900과 모바일320×568/360×800/390×844/430×932/가로640×430에서 150% 글자·글자 전체 노출·스크롤0·선택/후속 서술·NPC·새로고침/전환·세이브 보호를 검사한다.
- 스크린샷: `pages-first-*`, `pages-aftermath-*`, `pages-exam-*`. 모바일 검수는 Edge/Chromium 화면 크기 에뮬레이션이며 실제 휴대폰/Safari/Firefox는 미검증이다.
- 공개 주소: `npx tsx scripts/verify-pages-ui.ts https://jilzu001.github.io/demon-king-life/`.

## 검수 중 해결한 문제

- 최초 페이지 수를 측정한 뒤 선택지 버튼 공간/읽기 버튼 높이가 바뀌어 페이지 수가 다시 바뀌었다. 최초 측정 전에 버튼 문구와 표시 공간을 확정하도록 수정했다. 원문/분기를 바꾸지 않았다.
- 높이430px의 가로 화면/글자150%에서 선택 팝업의 고정 제목이 선택 버튼 중심을 가렸다. 높이500px 이하에서는 제목도 팝업과 함께 스크롤하도록 조정하고 실제 선택 실행까지 검사했다.
